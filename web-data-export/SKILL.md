# 发现并组合网页已有能力

## 核心思路

网页通常已经会做很多事：取得数据、翻页、读取文件、显示图表，有时还加载了压缩或格式转换组件。

**先找出网页已经会做什么，再把这些能力组合成用户需要的功能。**

例如，网站能逐张显示图片和分类，就可以研究如何重复读取、保留分类，并打包下载。没有“批量导出”按钮是寻找其他途径的起点；实际能取得多少数据、是否为原文件，仍要验证。

这项技能适用于导出数据、批量读取、检查缺失项、整理页面内容，以及增加本地筛选或下载按钮。只做用户要求的工作，不因发现其他接口而扩大范围。

## 先判断你能怎样执行

不要假设自己有浏览器控制工具，也不要依赖某个桌面客户端。

- **能操作浏览器：** 在工具允许的范围内观察页面、验证读取方式，并完成操作。
- **能运行本地代码：** 对公开数据或已有正式授权的 API，可以编写本地脚本处理。只有公开网址、没有登录能力时，不假装已访问私有数据。
- **只能与用户对话：** 由模型写代码，用户在自己的浏览器中运行，再把必要的运行结果带回来。也可以完成任务，不必要求用户安装浏览器控制插件。

这些能力可以组合。只缺少执行步骤时，不把整项调查重新交给用户；先完成当前环境能做的分析和脚本准备。

## 一、明确最终要得到什么

从对话和页面中确定对象、范围、结果。例如：

- “把这个数据集的全部图片下载下来，保留分类。”
- “把当前筛选结果的所有页整理成表格。”
- “给这个页面加一个检查重复项的按钮。”

区分当前页、当前筛选结果和全部数据。用户没有指定格式时，选择方便后续使用的格式：表格用 CSV 或 Excel，文件保留原格式，批量附件可放进目录或 ZIP。

范围清楚就继续；只在缺失信息会改变结果时询问。只要求解释原理或编写工具时，不擅自执行全量任务。

## 二、找到可以复用的数据与功能

按当前问题选择调查方式，不必把所有方法走一遍。

| 线索在哪里 | 怎么调查 | 能发现什么 |
| --- | --- | --- |
| 网站菜单、帮助、连接器 | 检查导出、批量操作和官方 API | 现成且容易维护的办法 |
| 页面里的表格、链接、图片 | 读取页面结构，也叫 DOM | 已显示的文字、链接和数据 |
| 网页加载数据的请求 | 观察翻页、切图、打开详情时的 Network 请求 | 列表、分页参数、详情和文件来源 |
| 网站公开的 JavaScript | 查找相关组件、调用过程和按钮显示条件 | 现成读取函数、文件处理组件、隐藏入口的原因 |
| 正常可用的页面操作 | 尝试翻页、选择、点击下载 | 可重复执行的人工流程 |

判断“已经取得证据”与“还只是推测”：代码里有导出函数，不证明当前账号能用；页面显示 30 条记录，不证明只有 30 条；预览图能保存，不证明它是原图。接口地址、函数用途和参数应来自观察、文档或实际验证，不能靠大量猜测。

遇到 blob: 地址时，它通常是浏览器中某个对象的临时引用，不能当成普通服务器下载地址。单个文件可尝试在原页面保存；批量处理应继续追踪网页创建它之前如何取得内容。媒体流的 blob: 也不一定对应一个完整文件。

## 三、选择最合适的执行方式

“从哪里取得能力”和“在哪里执行代码”是两个选择。Console 是执行入口，里面既可以提取页面，也可以调用已确认的读取功能。

| 方法 | 什么时候使用 |
| --- | --- |
| **官方功能、连接器或 API** | 已能完成任务时，直接使用 |
| **F12 → Console 脚本** | 一次性任务，需要利用当前页面、登录状态或网页已有组件 |
| **复用网页请求** | 已确认列表或文件读取请求，需要翻页或批量读取；可在浏览器内或合适的本地程序执行 |
| **提取页面内容** | 所需内容已经存在于页面中，不必重新取得 |
| **浏览器自动操作** | 页面流程可用，但接口不方便调用；自动重复点击、翻页和下载 |
| **本地 Python／JavaScript 脚本** | 任务较大，需要续传、重试、整理文件，且具备合法可用的数据访问方式 |
| **书签脚本、开发者工具 Snippets** | 短小代码需要偶尔重复使用；Snippets 是开发者工具内保存脚本的地方 |
| **用户脚本或浏览器扩展** | 用户需要长期增强特定网站；用户脚本可在指定页面加载，扩展适合更完整的跨页工具 |

选择能完成任务、用户步骤少、容易验证的方法。一次性导出通常不必制作扩展。只有用户需要长期使用时，才考虑持久化工具；编写工具不等于获准安装或授予额外权限。

可以组合方法。例如：分析公开代码找到读取函数 → 在 Console 中调用 → 用网页已加载的 ZIP 组件打包。复用组件前检查用途、版本和初始化副作用，不盲目导入未知代码。

## 四、没有浏览器控制工具时，怎样协作

采用“模型准备 → 用户执行 → 结果验证”的流程，让每一轮都有明确用途。

1. **模型先完成能做的调查。** 使用用户给出的页面内容、公开文档和公开前端代码。不要反复要求用户执行已经能从这些材料查明的步骤。
2. **缺少关键证据时，只索取最小材料。** 例如：某次翻页请求的路径、分页参数，以及少量已脱敏的响应字段。说明要查看哪里、哪些字段有用；不要索取整份 HAR、完整请求复制件、Cookie 或 Token。
3. **给出可检查的脚本。** 说明运行页面、预期行为和输出。一次性任务可让用户在已登录的原页面打开 F12 → Console 执行；先检查域名、对象或版本，防止运行在错误页面。
4. **先验证少量，再批量执行。** 有充分证据时，可以提供带预检和小样本验证的完整脚本，减少往返；不要一次给用户一堆没有解释用途的试探命令。
5. **根据实际结果继续。** 让脚本显示进度和必要的脱敏错误。只需要诊断时，不要求用户贴出整个数据集。遇到报错，查明原因后修改，避免让用户盲目重复运行。

无法取得私有页面的必要信息时，明确哪些部分尚未验证。只交付脚本就说“脚本已准备好”；用户确认下载完成或有本地检查证据后，才报告实际完成情况。遇到浏览器安全拦截或工具访问限制时，遵守相应要求，不指导关闭保护来继续执行。

## 五、先验证，再完成整项工作

先用少量有代表性的数据检查：
- 是否拿到了真正需要的内容，例如原文件、完整字段、正确的分类。
- 翻页是否有效，会不会重复第一页或只处理当前屏幕可见内容。
- 脚本是否只执行了预期操作；临时界面增强是否正常、能否撤销。

批量处理时控制并发，避免重复运行造成重复下载或重复修改。为同名文件安排唯一保存路径，保留原名对应关系。较长任务记录进度和失败项；临时网络故障有限重试，限流按提示退避，权限不足或登录失效时停止相关请求。

导出后核对实际数量、文件可打开性和关键关系，例如图片与标签、记录与附件、训练集与验证集。抽样检查要明确说是抽样；图表聚合数值不能冒充底层明细；文件非空或数量相同也不能单独证明完整正确。源数据在处理期间变化时说明时间范围与限制。

部分成功时保留成果并列出缺失项。交付文件或工具的位置，说明完成了什么、验证了什么、还有什么需要用户执行。把模拟测试、真实读取、发起下载和确认保存分别报告。

## 三个方法组合的例子

- **图片平台没有批量下载：** 分析公开代码 → 确认图片列表、分类和文件读取方式 → 在原页面运行脚本 → 下载图片和标签并打包 → 核对数量。
- **后台记录有几十页：** 观察一次翻页请求 → 确认筛选条件、分页和记录 ID → 批量读取并去重 → 导出表格。若只能通过 UI 取得，则自动翻页提取。
- **每次都要检查页面重复项：** 确认需要检查的字段 → 读取页面内容并验证判断规则 → 添加高亮或筛选按钮。一次使用可放在 Console，多次使用再做成书签或用户脚本。

## 必要边界

只处理用户有权访问且要求处理的数据。已有登录状态仅用于原服务的正常操作；凭据不进入聊天、日志、脚本文件或导出包。不绕过权限、付费、媒体保护或工具限制。

区分浏览器内的临时显示变化和真正提交到服务器的操作。导出或本地筛选不代表允许修改、删除源数据、上传到其他服务或扩大访问权限。遇到这些额外动作，按用户授权及当前工具规则处理。

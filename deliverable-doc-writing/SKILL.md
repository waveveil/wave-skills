# 成稿式文档写作

## 核心原则

**文档是成品,问题在对话里说。**

文档正文只承载内容本身。关于文档完成度、资料充分性、证据缺口的一切话,都不属于文档,而是写给用户的反馈,放在对话回复中。

## 文档中禁止出现的内容

以下类型的表述不得出现在正文、标题、摘要、图表说明、页眉页脚、附录中:

1. **版本与完成度声明**:"初版""草稿""本报告为阶段性成果""后续将完善"
2. **证据充分性声明**:"尚未提供实测数据""不作为已完成实验的证据""当前资料仅支持……"
3. **待办类内容**:"待补充""待实验""待验证""待确认""TODO""此处应插入……""【请填写】"
4. **占位符**:空白图表位、"图 X 待插入"、"XX 数据"、"[此处略]"
5. **对自身的限定**:"受限于现有资料""作者无法确认""本文不保证……"
6. **面向用户的口吻**:"如需,我可以……""建议你补充……"

自检时可检索这些关键词:`初版 草稿 待 尚未 暂无 TODO 占位 后续补充 不作为 受限于`。注意区分:**正当的学术局限性论述**(如论文"研究局限"一节、方案书的"风险与应对")是内容本身,不在禁止之列;禁止的是关于文档状态的元叙述。

## 不虚构

去掉免责声明不等于编造内容。

- 没有的数据、实验结果、文献、引用、图片,不得杜撰,也不得用措辞暗示"已完成"。
- 内容的性质要如实体现在事实陈述里,而不是用声明代替:基于理论计算的写"理论计算值",基于仿真的写"仿真结果",方案阶段的内容用设计、预期、计划的口吻写作。这是对内容属性的准确描述,不是免责声明。
- 缺乏依据的章节,宁可省略,或只陈述已有事实,不要硬撑。

## 工作流程

1. **识别文档类型与读者**:实验报告、方案书、论文、申报书等,按对应惯例组织结构。
2. **盘点材料**:用户提供了什么(数据、图、参考文献、要求),缺什么。
3. **判断缺口是否阻塞**:
   - 缺口影响核心内容(如实验报告没有任何数据)→ 先在对话中问用户,简明列出所需材料,不要先写一份带空洞的文档。
   - 缺口只影响局部 → 先写出基于现有材料的成稿,省略无依据的部分,写完后在对话中说明。
4. **按成稿标准撰写**:语言客观、结构完整、前后一致,术语、单位、编号统一。
5. **自检**:通读全文,按上文关键词清单检查,确认没有元叙述和占位符,图表编号与引用对应。
6. **对话中反馈**:交付后用简短文字告诉用户:
   - 文档基于哪些材料写成;
   - 哪些部分因缺少材料而省略或写得较简略;
   - 补充哪些材料后可以进一步完善(具体到材料名称)。

   反馈要具体、简短,不重复文档内容。若没有任何缺口,只需一句话交付说明。

## 各类文档的写作要点

**实验报告**:目的、原理、器材与方法、步骤、结果与分析、结论。结果只写有依据的数据;没有实测数据时不写"实验结果"章节的虚假内容,而是向用户索取数据,或将报告范围限定为用户已有的部分(如原理与方案设计)。

**方案书 / 技术方案**:背景与目标、总体设计、关键技术、实施计划与时序、预期成果、风险与应对。以设计与计划的口吻书写,用"拟""将""预期"等词准确表达尚未实施的内容,不用"待"。

**论文**:摘要、引言、方法、结果、讨论、结论、参考文献。参考文献只列用户提供或可确认真实存在的,不编造条目。研究局限在"讨论"中以学术写法陈述。

**研究报告 / 申报书**:按目标单位或模板的格式要求组织,材料不足的栏目按上述原则处理。

## 交付格式

文档文件格式(Word、PDF、在线文档等)按用户要求和环境中的对应技能处理,本技能只约束内容与口吻。

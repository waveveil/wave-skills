# 邮箱资料收集与归档

把分散在邮件附件、文件分享链接和正文中的材料整理成可继续使用的本地资料集。输出随任务选择：原始文件、汇总表、可追溯的处理记录、缺失清单或压缩包。只执行用户要求的部分，不为单独查缺件重新运行全部流程。

## 先确定范围与当前版本

从当前对话、已有目录和连接器中确定邮箱或本地来源、日期与时区、文件夹、筛选排除条件、归档单位和交付位置。范围已清楚时继续执行，缺失信息会实质改变筛选结果时才询问。

## 用户需要提供什么

只补问当前任务缺少的信息，已在对话、连接器或现有表格中的内容直接复用。

| 信息 | 最少需要什么 | 可以怎样省略或补充 |
| --- | --- | --- |
| 资料来源 | 要读取的邮箱账户或已连接账户；仅整理本地资料时给出目录。 | 已知当前资料目录时不再索要邮箱与凭据。邮箱客户端名称不代表服务商。 |
| 收集范围 | 起止日期、目标材料或筛选意图。 | 时间按用户时区处理并说明；已知的范围不重复询问。文件夹/标签从账户中读取后按目标选择。 |
| 读取权限 | 已连接账户的授权，或当前邮箱支持的登录方式。 | 先识别服务商再确定是 OAuth、客户端授权码、应用专用密码还是本地导出；不统一索要“邮箱密码”。 |
| 版本与排除 | 有特殊要求时说明按谁/什么去重、保留哪个版本，以及排除对象。 | 未规定版本规则时不删除独立事项，保留候选并记录重复；不能默认所有人只留最后一封。 |
| 整理结果 | 有要求时提供输出位置、字段、命名方式和文件格式。 | 否则使用当前工作区，保留原件并按任务需要提供简表和缺件结果。 |
| 特殊业务规则 | 仅在要从编号推导类别、年级、部门等时提供规则。 | 能从材料明确验证的映射不再索要；不能从号码规律臆造事实。 |

若确需一次收集说明，可使用这个简短模板；不要为了填满模板阻塞已经能开展的工作：

```text
来源：邮箱账户 / 已连接账户 / 本地资料目录
范围：开始日期至结束日期，材料目标，可选文件夹或标签
版本与排除：保留规则、排除对象（有特殊要求再写）
结果：保存位置、汇总字段、命名或格式要求（可省略）
```

登录授权另走对应渠道：优先现有连接器或用户在服务商页面完成 OAuth；确需授权码/应用密码时优先本地安全输入或临时环境变量，用户已提供的有效授权按当前范围继续使用。不要要求用户在聊天中提交主密码、短信验证码、恢复码或手工粘贴访问令牌，也不要为了只读收集索要 SMTP 发信配置。

续做任务先检查磁盘上的当前文件与表格：用户可能已补件、修改标识、删列、排序或重新排版。旧脚本、名单、聊天中的数量不是最新事实。按邮箱、项目编号等稳定键对齐，不按旧行号、昵称或目录顺序强行匹配。

按所需步骤读取参考资料：

- 识别邮箱服务商、判断需何种授权或如何导出：读 [references/provider-access.md](references/provider-access.md)。
- 读取邮箱、补取分享链接、确定“最新一封”：读 [references/mail-intake.md](references/mail-intake.md)。
- 提取字段、统一格式、命名目录、更新表格和压缩包：读 [references/organize-and-verify.md](references/organize-and-verify.md)。

## 收集与筛选

优先使用能完成任务的已连接邮箱工具或官方接口；授权的 IMAP 是可选途径，不限定邮箱厂商。使用现有本地资料即可完成任务时，不重新登录邮箱。授权码只在运行时读取，不写入技能、源码、日志或交付物。

先取得有限范围内的邮件元数据，再确定保留集。以用户指定时区的半开区间表示日期，例如某日开始至末日的次日零点。跨时区搜索可适度放宽服务端日期，随后精确过滤收件时间。保留实际运行截止时间，不把当天尚未到达的邮件算作已检查。

筛选同时考虑发件人、主题、正文线索和实际材料，不只依赖一个精确主题关键词。将广告、系统通知、指定排除对象和含糊记录分开，记录排除原因。

先明确去重单位：发件邮箱、项目、单据、邮件线程或文件。**同一发件人可能提交多个独立事项，不能默认只留一封。** 用户要求每人最新一封时，按同一时区的收件时间排序，使用稳定消息标识处理同时间情况。若最后一封没有所需材料，明确标记，不擅自用旧版本替换。

## 材料不能只看附件图标

分别处理以下来源，并在记录中保留来源类型：

| 来源 | 处理方式 |
| --- | --- |
| 普通附件 | 下载任务需要的全部文件，保留扩展名和原文件名记录。 |
| 超大附件、网盘、文件分享链接 | 核实邮件中明确提供的文件链接，取得实际文件并验证结果。 |
| 邮件正文 | 读取 plain/HTML 文本与表格；完整材料可能直接粘贴在正文中。 |
| 图片、扫描件 | 先判断是证件照、截图还是完整材料，再决定是否需要 OCR。 |

“没有普通附件”“只有照片”“正文含完整材料”“链接失效”“没有 PDF/Word”“完全没有提交材料”是不同结论。逐项说明，不用一个“无附件”状态混淆。

保存文件后核对字节数及 SHA256；分享服务提供大小或内容摘要时一并校验。不要把下载页 HTML、登录页或预览缩略图当成原文件。若采用内容哈希去重，要为所有相关人员或项目保留归属记录和可用引用，避免目录看似空缺。

## 字段与命名

优先读取正文、Word 表格或 PDF 中明确的标签字段，再用邮件标题和文件名交叉核对。不要把邮箱中的数字、QQ、电话等其他编号直接当作业务标识。异常或冲突保留原文及证据，不静默修正。

学号、工号、客户号等按文本处理；读取用户修改的 Excel 时同时检查实际值和显示格式，避免丢掉前导零。按编号推导年级、部门或类别，只在用户提供规则或已有材料能验证映射时进行，并按适用年级、批次分别确认。

目录命名采用用户指定格式，例如 `编号_名称`、`项目号_单位名`。只要求改目录名时，不顺带重命名内部文件。改名前核对对应关系、目标路径边界和重名；改名后同步当前清单、有效文件链接和已有交付压缩包，并确认文件内容未变。

## 当前文件夹完整性检查

对真实目录重新枚举，按用户要求的扩展名检查每个直接子目录。区分“任一种即可”与“每种都需要”，说明是否检查更深层目录。空文件和读取失败不能悄悄算作齐全。仅按扩展名检查时，不声称已验证文档内容。

可使用附带的只读脚本，例如检查每个资料目录是否至少包含一个 PDF 或 Word：

```text
python scripts/audit_collection.py --root <资料目录> --extensions .pdf,.doc,.docx --deep --hashes --report <检查结果.json>
```

`--match all` 表示每个指定扩展名都需要；默认 `any` 表示有其中任一种即可。脚本不会补件、改名、转换文件或访问邮箱。需要补齐格式时，先区分原件缺失与有正文但尚未转换，仅在授权范围内继续处理。

## 完成标准与交付

按当前任务核对必要的数量关系：范围内邮件、排除、保留事项、旧版本、附件记录、唯一文件、归档目录、未解决项。明确每个数字的计数单位，不要求邮件数、人数与文件数相等。

表格保留用户的当前布局，使用对应的表格技能完成必要编辑和导出检查。验证标识仍完整、主要字段可筛选、文件引用可用。续做的局部改动只修改相关内容，不能用旧生成器覆盖用户改过的表。

交付时直接给出结果位置、完成数量和仍需处理的具体对象。若来源可继续变化，说明本次检查截至何时。缺件结论必须来自当前检查，不从历史对话推断。

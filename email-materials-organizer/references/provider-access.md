# 主流邮箱接入与用户准备信息

维护核对日期：2026-10-28。认证政策、套餐及设置入口会变化，执行新任务前核对当前账户页面或厂商官方说明。下面是选择路径的参考，不代表这些服务已在当前环境逐一实测或已有连接器。

## 先识别服务，再请求正确的授权

1. 邮箱地址及用户已连接账户通常足够确定个人邮箱候选。自定义域名需确认实际托管商、登录入口和个人/组织账户类型；不能仅用品牌客户端名称或 MX 记录确认服务能力。
2. 先用已有连接器/API。只有确需新接入时，按该服务商要求让用户完成登录授权或提供专用客户端凭据。OAuth 的令牌取得和刷新由可用工具完成，不让用户手工粘贴令牌。
3. 用户自己完成服务商要求的验证码、MFA 或管理员同意流程；代理继续执行已授权的读取。不能通过关闭 MFA、解除组织限制或尝试其他账户绕过要求。
4. 若当前工具不能发起 OAuth、IMAP 被组织禁用、套餐不支持客户端或网络无法连接，明确实际限制。可以改用已授权网页会话、官方导出、本地完整邮件文件，或继续整理已有材料，不反复试密码。
5. 只有在用户确需并同意自建应用时才涉及应用注册、client ID、tenant ID 等配置。普通收集任务不默认要求用户创建云项目或提供管理员凭据。

| --- | --- | --- |

| 网易个人邮箱：163、126、yeah | 已连接账户或其允许的 IMAP/客户端授权密码。 | 用户在对应账户设置确认客户端协议与专用凭据，按当前域名的客户端设置读取服务器。免费、VIP、企业邮箱分开判断，不能把普通 163 设置套到全部网易产品。 |
| Gmail 个人账户 | 优先 Google OAuth/连接器/Gmail API；支持 OAuth 的 IMAP 也可用。 | 用户完成 Google 登录即可；个人 Gmail 的 IMAP 已默认开启，不再要求寻找旧版“启用 IMAP”开关。应用专用密码只在账户已启用两步验证、确实提供该功能且所选客户端需要时考虑，不能用普通主密码替代。 |

| Outlook.com、Hotmail、Live 个人账户 | Microsoft OAuth2/Modern Auth；优先已有 Microsoft 连接器。 | 用户完成 Microsoft 登录，并确认账户允许 IMAP（如果采用 IMAP）。不能把 `imaplib.login(账号, 普通密码)` 或“开两步验证后生成授权码”当成通用方案。 |

| Yahoo Mail 及其地区域名 | 支持的 OAuth/连接器，或官方客户端设置要求的应用密码。 | 按账户安全页生成可用应用密码；确认所属地区和品牌，不把网页登录密码作为脚本默认凭据。 |
| 腾讯企业邮箱 / 企业微信相关邮箱 | 企业允许的连接器或当前企业邮箱客户端接入方式。 | 自定义域名、实际租户服务、管理员是否允许 IMAP、当前专用密码/授权方式。与个人 QQ 邮箱分开，不能直接套 `imap.qq.com`。 |
| 网易企业邮箱、VIP 等网易付费产品 | 当前产品官方提供的客户端/API/导出方式。 | 产品类型、地区、登录入口、企业客户端参数与管理员策略；服务器和授权方式以该账号页面为准。 |
| 阿里邮箱 / Alibaba Mail | 组织开放的客户端方式，使用第三方客户端安全密码等当前支持的认证。 | 管理员需允许第三方客户端及相应 IMAP 权限；通用、香港和自定义域名等配置不同，按账户/官方页面确认。 |
| Zoho Mail | 官方支持的连接器或 IMAP；有 MFA/SSO 时按说明使用应用专用密码等方式。 | 账户类型、数据中心、IMAP 开关及套餐权限。新注册免费账户可能没有 IMAP，服务器也随账户和区域变化；不保证免费版可直连。 |
| Proton Mail | 官方支持的导出流程，或当前账户可用的 Proton Mail Bridge。 | Bridge 当前需要支持的付费计划；连接本机 Bridge 显示的地址、端口和专用凭据，不把它当普通公网 IMAP，不能假定云端连接器能访问用户本机 Bridge。 |
| 139、189、联通邮箱、Sina、Sohu、TOM、263 及其他服务 | 先查看当前服务官方客户端接入或完整邮件导出说明，再决定连接器、IMAP、网页或导出文件。 | 确认个人/企业/套餐差异、专用密码、服务器、历史邮件范围和管理员限制。未核实前不凭域名拼出 IMAP 地址，也不承诺全部套餐都有 IMAP。 |

只做邮箱收件材料读取不需要配置 SMTP，也不需要授予发信权限。某些 IMAP OAuth 服务的协议权限本身不能细分只读时，仍通过只读操作避免写入，不声称它等同于 API 的只读权限。

## 文件夹、分页与附件的差异

- 连接后读取真实文件夹/标签列表及特殊用途属性，再确定收件箱、归档或用户指定范围。不要把不同语言的收件箱名称硬编码为相同路径。
- Gmail 同一消息可能出现在多个标签。跨标签读取按服务的稳定消息标识（如 API message ID 或 `X-GM-MSGID`）避免重复；不能把线程当成单封邮件。
- API 必须跟随分页/继续令牌直到选定范围结束；IMAP 检查是否限制可同步文件夹或历史跨度。网页条数、第一页条数和全量匹配数可能不同。
- 租户的共享邮箱、委派邮箱和普通个人收件箱是不同读取对象，按现有权限选择，不扩大访问。
- 各家都有可能出现云盘/文件分享链接；QQ 超大附件、网盘链接、Google Drive、OneDrive/SharePoint、Apple Mail Drop 等均要按链接实际托管方及当前权限处理，不按收件邮箱厂商猜下载方式。收件邮箱授权不自动赋予独立云盘权限。
- 不将 POP 自动用作 IMAP 的无损替代：文件夹、已读状态及服务端保留行为不同。只有用户的材料范围确实能覆盖且明确保留服务端原件时才采用。

## 无法直接登录时仍可处理的输入

可处理用户已有的完整 EML、MBOX，或可由当前工具完整读取/导出的 PST/OST、客户端备份、附件目录；先核对实际可读内容及覆盖范围。PST/OST 不应直接当作 MIME 文本解析。截图、网页预览和仅同步的邮件标题不足以证明附件已导出。

导出路线最少需要“完整导出的位置、日期范围、目标材料及整理目的”。继续本地整理时不再请求邮箱授权。导出时间缺少时区、发送时间与收件时间不一致，或没有原始邮件时，只能说明实际可验证的范围。
